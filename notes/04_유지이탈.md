# 04. 유지 · 이탈의 정의

> ⚠️ **합성 데이터 기준.** 데이터 → [[01_데이터]] · 실측 → [[02_퍼널실측]]

## ★ 먼저 — 우리 도메인엔 "유지"가 그대로 오지 않는다

수업 도메인(통신사)은 **가입자가 남는가**를 본다. 대상이 계속 존재한다.
우리는 다르다 — **수주는 남는 것이 아니라 끝나는 것이다.** 출하되면 그 수주는 사라진다.

그래서 유지의 주체를 정하는 것이 오늘의 첫 판단이었다.

| 후보 | 그레인 | 판정 |
|---|---|---|
| 고객사가 계속 발주하는가 | 고객사 | ❌ **못 잰다** — 아래 참조 |
| **수주가 끝까지 완결되는가** | **수주 1건** | ✅ **채택** — 퍼널과 그레인이 같다 |
| 제품도번이 계속 생산되는가 | 제품도번 | 🟡 1,200종 — 이제 가능하나 이번엔 안 함 |

### 고객사 이탈을 못 재는 이유

| 고객사 | 수주 건수 | 최근 무발주일 |
|---|---:|---:|
| E사 | 36,595 | 1일 |
| A사 | 33,868 | 1일 |
| C사 | 11,506 | 1일 |
| B사 | 10,806 | 1일 |
| D사 | 3,225 | 1일 |

**5곳 전부 어제까지 발주 중이다. 이탈 고객사 0.**
표본이 **5뿐**이라 이탈률을 내도 의미가 없다 — 한 곳만 빠져도 20%가 된다.
(규모를 96,000건으로 키워도 고객사 수는 그대로다. **표본 부족은 행 수로 못 푼다.**)

> **"관측 기간 부족"이 아니라 "표본 부족"이다.** 억지로 만들지 않고 한계로 적는다.
> 실데이터에서는 고객사가 수십~수백이므로 그때 다시 본다.

## 조작적 정의 (명세 5행)

```
납기일이 지나고 30일이 더 흘렀는데도 출하되지 않은 수주 = 이탈
```

| | |
|---|---|
| 그레인 | 수주 1건 (수주ID) |
| 판정 시점 | 기준일(2026-08-29) |
| 모집단 | **완주 코호트 (접수 후 61일+)** · 납기일 결측 제외 |
| **이탈률** | **4.3%** (3,232 / 74,424) |

### 왜 "납기 + 30일"인가

- **납기 도래만으로는 부족하다** — 며칠 늦는 건 지연이지 이탈이 아니다.
  실측상 **지연 출하의 최대가 24일**이었다(중앙값 13일).
- **30일을 넘기면 정상 지연의 범위 밖**이다. 그때는 밀린 것이 아니라 멈춘 것으로 본다.
- 근거가 데이터 안에 있다 — 임의로 고른 숫자가 아니다.

## ★★ 생존 편향 점검 — 코호트 절단이 실제로 착시를 지웠다

교안의 사례(CS 문의 0건 이탈 19.0% vs 4건+ 2.5% = 7.6배 → 월평균으로 나누니 차이 없음)와
**같은 구조가 우리 데이터에서도 나왔다.**

| | 절단 없음 (96,000건) | **코호트 61일+ (79,992건)** |
|---|---:|---:|
| 이탈률 | 3.6% | 4.3% |
| **평균 관측기간 (잔존)** | 180.4일 | 211.7일 |
| **평균 관측기간 (이탈)** | 216.0일 | 216.3일 |
| **차이** | **+35.6일** ⚠️ | **+4.6일** ✅ |
| 누적 이벤트수 (잔존 vs 이탈) | 6.04 vs 4.05 | 6.24 vs 4.05 |
| **월평균 이벤트수 차이** | **−1.59** (3.3배) | **−0.43** (1.6배) |

### 무슨 일이 일어났나

**절단하지 않으면 잔존 집단에 최근 접수건이 대거 섞인다.** 이들은 관측 기간이 짧은데
이벤트는 초반에 몰려 찍히므로 **월평균이 부풀려진다**(2.29 → 1.12).

그 결과 *"잔존 수주는 활동이 3.3배 많다"*는 결론이 나온다.
**코호트를 자르면 1.6배로 줄어든다 — 차이의 3.7배가 관측 기간의 그림자였다.**
관측기간 차이도 **+35.6일 → +4.6일**로 거의 사라진다.

> **떠난 것은 떠난 뒤에 아무것도 하지 않는다.**
> 관측 기간이 다른 대상을 비교하면 **효과가 아니라 시간을 재게 된다.**

### 그런데 남은 1.6배도 지표로는 쓸 수 없다

비율로 바꾼 뒤에도 잔존 1.12 vs 이탈 0.69로 차이가 남는다. 하지만 이건 **순환논리다**:

```
미완결 → 출하 이벤트가 없음 → 이벤트 수가 적음
```

**이벤트 수가 적어서 이탈한 게 아니라, 이탈했으니 이벤트가 적다.**
원인이 아니라 결과다. 선행지표로 쓰면 *"이벤트를 더 찍으면 이탈이 준다"*는 헛소리가 된다.

> 교안의 *"없음도 결과다"*가 여기 걸린다 — **이 데이터에는 이탈 선행지표가 없다.**
> 있었으면 무엇을 봤을까: **공정 착수 지연일 · 자재 결품 이력 · 계획 변경 횟수**.
> 이 셋은 지금 데이터에 없다 → **8주차 요구사항**이 된다.
