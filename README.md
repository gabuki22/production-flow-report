# 생산 흐름 리포트

**발주가 어디서 막히고 얼마나 밀리는가.** 자동차 부품 사출·도장 공장의 수주 흐름을
발주 접수부터 출하까지 11단계로 세고, 막히는 자리를 찾아 리포트까지 내는 앱.

데이터기반의사결정 과정 8주차 과제로 만들었고, 골격에서 갈라져 나온 뒤
**도메인에 맞게 정의를 갈아엎은 실전본**이다.

---

## ⚠️ 데이터는 전부 합성이다

실 ERP 반출이 되지 않아 **스키마와 값 체계만 복제**했다.
**방법은 확인할 수 있으나 판정은 실데이터로만 할 수 있다.**
여기 어떤 수치도 실제 회사의 실적이 아니다.

임계값(납기 준수율 90/80 · 불량률 4/5)만은 **현장 기준 구술**에서 나온 실제 값이다.
통계적 변동폭이 아니라 **사업이 감내할 수 있는 선**에서 그었다.

---

## 켜는 법

```bash
pip install -r requirements.txt
python -m streamlit run app.py
```

데이터(`data/*.parquet` 7종 · 138만 행)는 저장소에 들어 있어 따로 만들 필요가 없다.
다시 만들려면 `_generator/` 인데, **값 풀(원천 자료)은 공개하지 않아** 그대로는 안 돈다.

## 무엇을 보는 앱인가

```
발주접수 → 영업계획 → 생산계획 → 지시서작성
  → 사출 → 지그삽입 → 도장 → 레이저 → 인쇄 → 검사 → 출하
              ↑                                    │
              └──────── 미납확인 ←─────────────────┘
```

**그레인은 발주 1건(수주ID)이다.** 이벤트 행이 아니라 수주 고유값으로 세고,
한 수주가 같은 단계를 두 번 밟아도(미납이 다음 주기로 되돌아온다) **최초 도달만** 센다.

| 지표 | 계산식 | 분모 |
|---|---|---|
| **납기 준수율** (주지표) | 납기내출하 ÷ 납기 도래 | 납기 도래 전체 |
| **불량률** (가드레일) | 불량수량 ÷ 검사수량 | 수량 가중 |
| 긴급품 비율 | 긴급품 ÷ 완주 코호트 중 납기 도래 | 완주 코호트 |
| 지연 출하율 | 지연출하 ÷ 출하완료 | 출하된 건 |

★ **분모를 '납기 도래 전체'로 둔 이유** — 출하한 건만 세면 미납이 분모에서 빠져
**어려운 건을 미룰수록 지표가 올라간다.** 굿하트의 법칙이 그대로 걸린다.

★ **우리 병목은 새는 것이 아니라 밀리는 것이다.** 퍼널 전환율로는 축 간 격차가
최대 0.63%p 뿐이라 아무것도 안 갈리는데, 같은 축을 납기 준수율로 보면 4.24%p 갈린다.
**무엇을 쪼개느냐가 어느 축으로 쪼개느냐보다 크다.**

## 골격에서 바꾼 것

### ★ "이탈"을 **긴급품**으로 바꿨다

현장 확인: *"납기가 지나면 최대한 빨리 납품하려고 노력해야함. 긴급품이 됨"*

통신사의 이탈은 고객이 **떠나서 사라지는 것**이다. 우리 수주는 납기가 지나도
사라지지 않는다 — **더 급해질 뿐이다.**

| | 골격 | **이 앱** |
|---|---|---|
| 이름 | 이탈률 | **긴급품 비율** |
| 정의 | 납기 + **30일** 유예 후 미출하 | 납기가 지나고 미출하 (**유예 0**) |
| 대응 | 되찾는 일 | **먼저 내보내는 일** |

**유예를 없앤 이유** — 현장은 납기 다음 날부터 급하지, 한 달을 기다려 주지 않는다.
늦게라도 출하된 건은 긴급품이 **아니다.** 이미 나갔으므로 `지연 출하율` 로 따로 센다
(둘을 합치면 `1 − 납기 준수율` 과 같아져 지표가 겹친다).

### 해석과 제안은 자동 생성하지 않는다

**가르는 질문 하나** — *이 문장이 틀렸을 때 누가 책임지는가?*

| 자동 5장 | 사람 3장 |
|---|---|
| 요약 · 방법 · 결과 · 실험 · 한계 | **배경 · 해석 · 제안** |

해석과 제안을 자동화하는 순간 **책임의 주체가 사라진다.** 비어 있으면
`(작성되지 않음)` 으로 찍는다 — 채우면 아무도 빈 줄 몰라서다.

### 못 믿을 때는 계산하지 않는다

표본 100건 미만 · 기간 28일 미만 · 배정 SRM p<0.001 — 하나라도 걸리면
**지표를 아예 계산하지 않는다.** 계산해 놓고 숨기는 것이 아니다.
계산하면 값이 변수에 들어 있어 **리포트·로그로 샌다.** 손에 없으면 못 쓴다.

## 확인하고 바꾼다

```bash
python -X utf8 tests/test_metrics.py    # 숫자 검산 — 현장 실측 대조표
python -X utf8 tests/test_guards.py     # 망가뜨린 데이터를 거르는가
python -X utf8 tests/test_app.py        # 화면·게이트·PDF 까지 조작
```

**HTTP 200 은 렌더 성공이 아니다.** 버튼을 눌러 보고 게이트를 통과시키고
PDF까지 만들어 봐야 "됐다"고 말할 수 있다.

---

## 이 저장소에 없는 것

문서 곳곳에 `mydomain/` · `my-report/` 같은 옆 폴더가 나온다. **여기엔 없다** —
같은 작업 공간의 다른 폴더이고, 원천 자료와 수업 진도가 들어 있어 공개하지 않는다.
읽는 데 지장은 없다. 이 앱이 그 폴더들을 `import` 하지 않기 때문이다.

강사가 배포한 참고 문서와 원천 데이터도 빠져 있다. 무엇을 왜 빼는지는
`배포제외.txt` 에 적혀 있고, **검사(`tests/test_guards.py` 11절)가 훑는 범위를
그 파일이 정한다** — 안 훑는 것은 안 내보낸다는 뜻이다.
